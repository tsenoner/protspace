## Context

The explore page is a React skeleton (`apps/web/src/pages/Explore.tsx`) that renders seven Lit
elements from `@protspace/core` and hands them to a plain TypeScript runtime
(`apps/web/src/explore/`), which wires them together by element id. The large elements carry most
of the behaviour: the legend (about 3,300 lines in `legend.ts`), the scatterplot (2,300), the control
bar (2,100) and the figure editor (`publish-modal.ts`, 1,600).

PR #526 (`perf/improvements`, draft) made the page 20–80× faster at 573K proteins and cleaned up the
renderer. This change builds on that branch and leaves its performance intact.

Three audits of the page, at `perf/improvements` 7e94b858, found:

- **Layout.** The control bar needs about 1,600 px for one row. It wraps to two rows at 1280 px and
  three rows (about 135 px tall) at 1024 px. The legend is fixed at a quarter of the width with
  46 px rows, so long names break mid-word ("metalloproteinas e") and about 14 rows fit. Opening a
  structure squeezes the legend to about 8 rows. The header is the marketing site's navigation and
  nothing names the loaded dataset. No layout state is saved.
- **Style.** Core stylesheets hold 159 hard-coded colours. 18 font sizes are in use against 5 type
  tokens. There are about 35 button styles in 9 groups, 9 input looks, at least 7 ways to show
  "selected", 41 focus rules in four styles, 57 native `title` tooltips, 43 inline SVG icons in two
  stroke styles, and two emoji used as icons. Four different blues appear. The React shell and the
  components both define `--primary`, `--border`, `--muted` and `--radius` with different meanings
  (`--radius` is 12 px in one, 4 px in the other). Each Lit component re-declares the token values on
  its own `:host`, so a theme set on the page cannot reach inside. `index.css:146` scales the root
  font size with the viewport from 1380 px, so the base size drops from 16 px to 12 px between
  1379 and 1380 px and a 1440 px laptop renders every rem-sized component about 22% smaller.
- **Workflows.** Search drops unmatched pasted IDs silently. Escape clears the selection with no undo,
  even from inside the figure editor. Nothing on the plot says when the view is filtered or isolated.
  The query builder's Cancel keeps edits and its Apply is disabled without a reason. Filter, Export
  and the figure editor are three different kinds of container for similar jobs. The loading
  overlay, recovery banner and toasts look unrelated. Popovers and dialogs are positioned with
  `position: fixed` inside shadow roots, so any ancestor with `overflow`, `transform` or `contain`
  clips them: the legend's info popover is already clipped by the right panel at 1440×900.

The local branch `feat/mobile-responsive` (55 commits, based on an older `main`, never pushed)
makes the page usable on phones: a fixed full-height screen, a foldable legend panel, a structure
bottom sheet that opens folded, a "More" sheet for the control bar, and 38 phone e2e tests. It
rewrites the same layout files this change rewrites.

The look was chosen with mockups during brainstorming. The chosen screens are kept in
[`mockups/`](mockups/) as the visual reference for implementation.

## Goals / Non-Goals

**Goals:**

- The explore page looks and behaves like a mature desktop tool: one visual language, one set of
  controls, a layout that never wraps, and text a scientist can trust (no internal names, no
  grammar slips).
- A collapsible, resizable sidebar for the legend and the structure viewer, with the structure able
  to float over the plot.
- The everyday tasks (load, colour, search, select, isolate, filter, view a structure, export) take
  fewer steps and always say what happened.
- Phones and tablets get the same product, absorbing the mobile branch.
- A dark theme that ships, next to the light one.
- Cleaner code: the largest elements split into focused pieces, copied styles and dead code deleted,
  one way to do each recurring job.
- No performance regression against `perf/improvements` at 573K.
- Documentation, tour, screenshots and GIFs match the new UI, and are regenerated by script.

**Non-Goals:**

- The landing page (it has its own redesign branch) and the VitePress docs theme.
- New analysis features beyond the workflow fixes listed here.
- Changes to the bundle format, the Python CLI or the Colab notebooks.
- A native app, PWA install or offline mode.
- Translations.

## Decisions

### 1. The workbench layout

The page becomes a workbench (mockup: [`mockups/workbench-light.png`](mockups/workbench-light.png)):

- **App bar** (48 px): the wordmark (links home); the dataset name and protein count, which opens a
  menu to switch to an example or import a file; search in the centre (⌘K / Ctrl+K); Import and
  Export; the theme switch; a help menu (docs, keyboard shortcuts, tour); Feedback; GitHub. The
  site's Home / Docs / Explore / Resources navigation leaves this page; Docs moves into the help
  menu. The plot's Tips & Shortcuts popover and its tour button move into the help menu as
  "Keyboard shortcuts" and "Take the tour".
- **View bar** (44 px): how the plot is drawn. Projection (with the projection's "how it was made"
  details beside it), Color by, Contours, Filter. It never wraps: labels shorten first, then the
  least-used items move into a "More" menu.
- **Plot**: fills the rest. A small tool strip in the top-left corner (move/zoom, box select, lasso
  select, fit to view); the protein count and status chips in the bottom-left corner.
- **Sidebar**: on the right, flush with the plot (no card margins).

Alternatives considered: keeping today's card layout and making it consistent ("Refined"), which
keeps paying the margins and the site header in plot space; and a canvas-first layout with every
panel floating over a full-bleed plot, which covers points and dates fastest.

### 2. Sidebar: stacked panels, an icon rail, and a floating structure

The sidebar shows the legend on top and the structure viewer below, separated by a divider the user
drags (mockup: [`mockups/sidebar.png`](mockups/sidebar.png)). A 44 px icon rail on the right edge
lists the sidebar's panels: Legend, Structure, Filter. The rail stays when the sidebar collapses, so
any panel is one click away; a dot on the Structure icon means a protein is loaded. Filter opens in
the sidebar in place of the legend (decision 14); the structure stays docked below whichever panel
is open.

- The sidebar's left edge is draggable (about 240–480 px).
- A button in the structure's header pops it out into a floating card over the plot, draggable by
  its header and resizable from its corner; another button docks it again
  ([`mockups/structure-floating.png`](mockups/structure-floating.png)). Floating is desktop-only
  (951 px and wider).
- When the sidebar is collapsed and the structure is docked, clicking a protein does not force the
  sidebar open: the rail's Structure icon gets its dot and the protein's tooltip offers "View
  structure". In floating mode the card appears.

Alternatives considered: a sidebar that hides completely (nothing on screen hints at the legend or a
loaded structure once hidden), and a legend-only sidebar with the structure always floating (the
card covers points and splits attention). The user chose the rail and asked to keep the floating
structure as an option.

### 3. The plot keeps the data's proportions

`DataProcessor.createScales` (`packages/utils/src/visualization/data-processor.ts`) maps x and y to
the plot's width and height independently, so the clusters' shape depends on the window, and
toggling a 300 px sidebar would stretch or squeeze every cluster by about 30%. The figure export
path computes its own scales with the same rule (`export-renderer.ts`, `createExportScales`).

Both now use one scale for both axes: the padded data extent is fitted inside the plot area with
`min(width / dx, height / dy)` and centred
([`mockups/plot-proportions.png`](mockups/plot-proportions.png)). Wide windows show margin at the
sides. One shared
function serves the live plot and the export, so a figure has the same shape as the screen. The
figure editor's zoom insets, which pass an explicit data domain, keep doing so.

Alternatives considered: stretching to fill (today's behaviour, which reshapes clusters on every
toggle) and stretching on load but freezing the scale on panel toggles (which keeps today's look but
makes the result depend on when the view was last reset).

This changes how existing plots look, especially PCA plots whose axes span very different ranges,
which now show as a band instead of filling the box. Pixel baselines that assumed stretching are
re-recorded.

### 4. One redraw per layout change

At 573K one plot resize costs about 95 ms of main-thread time plus a grid rebuild of about 30 ms
(`perf/README.md`), and the scatterplot's `ResizeObserver` reacts to every size change. Animating
the plot's width would pay that on every frame.

- A panel change resizes the plot exactly once. Opening: the sidebar slides in over the plot, then
  the plot shrinks. Closing: the plot grows first (under the sidebar), then the sidebar slides out.
  Dragging the sidebar edge or the divider moves the panel over the plot; the plot resizes when the
  drag ends.
- On resize the zoom transform is adjusted so the point at the centre of the view stays at the
  centre. Today zoom and pixel translate survive a resize but the data under the centre drifts.
- A new perf scenario, panel toggle, is budgeted at one render and one grid rebuild per toggle.
- Perf runs pin the layout (sidebar open at its default width, structure docked and closed) and the
  light theme. The sidebar's width sets the plot size, which feeds the point scale and the Auto
  contour strength, so an unpinned layout would make runs incomparable.

Alternatives considered: animating the plot's width (stutters at 573K), and keeping the canvas
full-width under the panels (no resizes at all, but the fit must then ignore a covered strip whose
width changes, and points under an opaque sidebar are drawn for nothing).

### 5. Design tokens on the document root

- One stylesheet in core, `packages/core/src/styles/theme.css`, is the single source of the design
  values. Every variable is prefixed `--ps-`, so nothing clashes with the shadcn names the landing
  page uses. It has three layers: raw ramps (the slate greys and the cyan scale); roles, which the
  themes set (surface, raised surface, sunken surface, border, strong border, text, muted text,
  faint text, accent fill, accent text, accent tint, danger, warning, success, focus, scrim, plot
  background, the neutral point greys); and sizes (control heights 28/32 px, list row 28 px, radius
  6 px, the type scale, spacing, motion durations, layers).
- The variables live on `:root` under `[data-theme="light"]` and `[data-theme="dark"]`. CSS custom
  properties inherit into shadow roots, so every component reads them without importing anything.
- Components only read tokens. The current `tokens` export, which re-declares values on each
  component's `:host`, goes, because a value declared on `:host` blocks the page's theme.
- Core adopts `theme.css` into the document once, when it is first imported, so an embedder gets a
  working theme with no setup. A page overrides any token with a more specific selector.
- Tailwind 4 in `apps/web` maps the same variables in `@theme inline` (e.g. `bg-ps-surface`), so
  React code and Lit code draw from one list.
- A unit test fails when a core stylesheet contains a raw colour, a pixel font size or a `var(--…)`
  that `theme.css` does not define, and when `theme.css` defines a token nothing uses.

Alternatives considered: keeping per-component tokens (the cause of the drift), and generating CSS
from a TypeScript token module (a build step for no gain: the CSS file is readable on its own, and
the test checks it).

### 6. Palette: Cool

Slate greys with ProtSpace's cyan (`#00a3e0`) as the accent (mockups:
[`workbench-light.png`](mockups/workbench-light.png), [`workbench-dark.png`](mockups/workbench-dark.png),
and the controls at real size in [`controls.png`](mockups/controls.png)). Cyan marks selection, focus and the primary action and
nothing else. Text in the accent colour (links, the active tab, the selected menu item) uses a
darker cyan (`#0284c7` light, `#38bdf8` dark) because `#00a3e0` on white is below the 4.5:1 contrast
WCAG AA requires for text.

Alternatives considered: neutral zinc greys (generic, colder in the dark theme) and a navy app bar
for brand presence (pulls the eye from the plot and loses its contrast in the dark theme).

### 7. Type: Inter, fixed sizes

Inter, self-hosted through `@fontsource-variable/inter`, with `system-ui` as the fallback and
`font-display: swap`. The font is not loaded from the Google Fonts CDN, which sends visitors' IP
addresses to Google and is a GDPR problem for a German research institute. The scale is 12, 13, 14,
16 and 20 px, plus 11 px for captions only, at weights 400, 500 and 600. Counts use tabular figures.

The viewport-scaled root font size (`index.css:146`) is removed: the workbench is designed in fixed
pixel sizes, and larger screens get more plot instead of larger chrome.

Alternative considered: the system font stack, which needs no download but renders differently on
each OS, which matters for the screenshots in the docs.

### 8. Building blocks in core, built on the platform

A small kit of Lit elements in `packages/core/src/components/kit/`, prefixed `ps-`, used by every
feature element and by the React shell alike (React 19 passes properties and events to custom
elements):

| Element                                    | Purpose                                                                                            |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| `ps-button`                                | primary, secondary, ghost, danger; 28 or 32 px                                                     |
| `ps-icon-button`                           | icon-only; requires a label, shown as its tooltip and used as its accessible name                  |
| `ps-input`, `ps-select`                    | text input; single choice as a styled native `<select>`, so phones keep their own picker           |
| `ps-menu`, `ps-menu-item`                  | grouped, searchable, checkable menus                                                               |
| `ps-popover`                               | anchored panel (the native `popover` attribute)                                                    |
| `ps-dialog`                                | modal window (the native `<dialog>`, `showModal()`), with a full-screen size for the figure editor |
| `ps-tooltip`                               | hover and focus label, replacing the 57 native `title` tooltips                                    |
| `ps-segmented`, `ps-switch`, `ps-checkbox` | small choice controls                                                                              |

Popovers and dialogs render in the browser's top layer, so no `overflow`, `transform` or `contain`
on an ancestor can clip them, and `<dialog>` brings focus containment, inert background and Escape
for free. `@floating-ui/dom` positions popovers next to their anchor, because CSS anchor positioning
is not yet in all target browsers. Icons come from Lucide only (`lucide` for Lit, `lucide-react`
already in the shell), at one stroke width (1.75) and 14/16/20 px; the emoji and text-glyph icons go,
including the ⚡ that marks predicted annotations in the annotation picker and the legend header.
Focus uses one `:focus-visible` ring everywhere, with a `forced-colors` fallback. Panels and popovers
animate for 120–200 ms; the plot never animates; `prefers-reduced-motion` turns the animations off.

Alternatives considered: Shoelace (a large dependency whose own look must be overridden piece by
piece, in maintenance while its successor splits into free and paid tiers) and rewriting the chrome
in React with Radix (about 7,000 lines of working Lit rewritten, and the end of the embeddable
components the developer docs describe). Target browsers are the last two versions of Chrome,
Edge, Firefox and Safari, which all support the `popover` attribute and `<dialog>`.

### 9. The control bar is split

`protspace-control-bar` is replaced by elements that each own one job, so the app bar, view bar and
plot can each hold their own: the projection picker, the annotation picker (`annotation-select`
already exists), the contours menu, the filter panel (the query builder), search (exists), the
export menu, the import menu, and the plot's selection tools. The behaviour the control bar
coordinated today (auto-sync with the scatterplot, the Escape handling, the selection mode) moves
into controllers in `apps/web/src/explore/`, next to `control-bar-events.ts`. **BREAKING** for
anyone embedding `protspace-control-bar`; `@protspace/core` is not published, and the developer docs
change in the same PR.

### 10. Layout state

A small store, `apps/web/src/explore/layout-state.ts`, holds the sidebar's open state, width, divider
position, active panel, the structure's docked/floating mode and floating rectangle, and the theme
choice. The React shell subscribes with `useSyncExternalStore`; the runtime reads and writes it
through the same module. It persists to one localStorage key, `protspace:layout:v1`, wrapped in
try/catch so private windows still work. Layout is never written to the URL, so a shared link never
imposes the sharer's layout. The theme choice gets its own key, `protspace:theme`, which an inline
script in `apps/web/index.html` reads before first paint (decision 16).

### 11. One layer stack for Escape and closing

A layer stack in core (`kit/layers.ts`) records which popovers, menus, dialogs, sheets and the
figure editor are open. Escape works through one order: the top open layer first, then the EAT
provenance connectors, then the selection; each press undoes one step. Today Escape passes
through the figure editor and the projection details panel and clears the selection. Clicking outside closes popovers the same way everywhere:
a press and release both outside, so a drag that ends outside does not close anything. This replaces
the Escape handling in `control-bar.ts` and the legend's own focus trap.

### 12. Legend

- Rows are 28 px (40 px on touch): colour dot, name, count right-aligned in tabular figures. Long
  names end in an ellipsis and show in full on hover; nothing breaks mid-word.
- On hover a row shows an eye (hide/show), a drag handle (reorder) and a "⋯" menu with "Show only
  this" and "Colour and shape". The existing click (hide/show), double-click (show only this), and
  keyboard actions (arrows, Enter, `i`) stay as shortcuts; `i` is added to the shortcut list.
  Hidden categories stay in the list, dimmed, with a crossed-out eye.
- The header shows the annotation's display name, never its raw key, then its info button, a sort
  button that shows the active order (by count, by name, or the user's own), and settings. The demo
  list today looks sorted by count but is not (282 sits above 289); showing the active order makes
  that visible.
- "Other · N categories" opens a searchable popover listing those categories with their counts and an
  "Add to legend" button each, replacing the "Extract from Other" modal.
- Settings become a popover under the gear. Changes apply as they are made (debounced), as the colour
  picker already does, and "Reset" restores the defaults; the Save/Cancel pair goes. The palette is
  picked from swatches instead of a native `<select>`. Category order moves out of settings into the
  list itself (drag, or the sort button). Persistence keeps today's per-dataset, per-annotation key,
  so saved settings carry over.
- The colour and shape picker, the predicted-annotation (EAT) controls, the score strips and the
  numeric legends keep their behaviour and take the kit's controls and tokens.
- `legend.ts` is split into the legend (state and wiring), the list, the row, the header, the Other
  popover, the settings popover and the EAT controls.

### 13. Selection, status and undo

- Selection tools live on the plot (box, lasso); a plain click still selects one protein, and
  ⌘-click (Ctrl-click) adds or removes one, as today. Shift stays reserved for category focus.
- With a selection, a bar appears at the bottom of the plot: "12 selected · Show only these · Zoom
  to them · Copy IDs · Clear". Clear and Isolate leave the toolbar, where they sat greyed out.
- When the view is narrowed, chips in the plot's bottom-left corner say so: "Filtered · 2
  conditions", "Showing only 3 categories · 2 steps", "4 categories hidden". Each opens the place to
  change it and has an ✕ to remove it.
- ⌘Z / Ctrl+Z undoes, and ⇧⌘Z / Ctrl+Shift+Z redoes, selection changes, "show only" steps and
  filter apply/reset, when focus is not in a text field. The history lives in the interaction
  controller and holds protein-id sets, not plot state.
- Reset filters and New figure show a notification with Undo. Clearing stored data (the recovery
  banner) asks for confirmation instead, because the OPFS copy cannot be restored.

### 14. Filter in the sidebar

The query builder becomes the sidebar's Filter panel (rail icon), so the plot stays visible while a
filter is built. A live count shows how many proteins the draft matches, computed off the render
path. Edits are a draft until Apply; Cancel discards the draft and returns to the applied filter
(today Cancel keeps the edits). When Apply is disabled the panel says why ("Choose a value for
condition 2"). Removing the filter is one click on the Filter chip's ✕.

The modal used to stop the EAT reliability slider and the query builder from being edited at the
same time; the side panel allows both. The slider stays an immediate control: it changes the
applied filter at once and also updates the reliability condition in an open draft. Editing that
condition in the draft moves the slider only when the draft is applied.

### 15. Search, messages, import and export

- **Search.** A pasted list reports "12 of 15 found" with the missing IDs listed and copyable. An
  unknown single ID shows "No protein P12345 in this dataset" instead of clearing the box. A single
  hit pans and zooms to the protein; several hits are selected, and the selection bar offers "Zoom
  to them".
- **Notifications.** One style (Sonner, restyled from the tokens) with a close button, placed at
  the plot's bottom edge so it never covers the legend. A notification carries up to two actions,
  each a link or a callback (Retry, Undo, Report a bug). Every export confirms.
- **Loading.** The overlay takes the kit's look and tells the truth about the data: "Reading your
  file in the browser" for local files; only FASTA files go to the server, for embedding, and the
  Import menu says so before upload. The rocket emoji and the inline styles go. The overlay keeps
  its id `#progressive-loading`, still blocks the page while a load runs, and keeps the example
  download's progress and Cancel; the plot keeps `#myPlot`. The e2e helpers and the perf suite
  key on both ids.
- **Empty state and drop target.** If nothing is loaded the plot shows "Drop a file or pick an
  example". Dragging a file anywhere over the workbench shows a drop area; today the scatterplot
  handles drops and sets an attribute that nothing styles. Drop handling moves to the shell.
- **Import menu.** The Import button and the dataset name open the same menu: the examples, the last
  imported file, and "Open a file…", with the accepted formats listed.
- **Export menu.** Figure editor, quick PNG, quick PDF, protein IDs, data bundle. The note that
  contours are not part of quick exports moves from a hover title into the menu.
- **Figure editor.** Becomes a full-screen `ps-dialog`: Escape closes it, focus is contained, and
  its "Cancel", which already keeps the editor state, is renamed "Close". `publish-modal.ts` is
  split along its sections.
- **Structure.** The protein tooltip gets "View structure". With several proteins selected, the
  structure header lists them and the user picks which one to show, instead of always the last.
- **Text.** Annotation display names everywhere (tooltips, settings titles); counts pluralised with
  `Intl.PluralRules` ("1 protein selected").

### 16. Dark mode

- A theme switch in the app bar (in the More sheet on phones): System (default), Light, Dark. The
  choice is stored under `protspace:theme`; an inline script in `index.html` sets `data-theme`
  before first paint, so the page never flashes white. System follows `prefers-color-scheme` live.
- Everything on the explore page follows: shell, kit, legend, tooltips, dialogs, the loading
  overlay, notifications and the tour. The explore root sets `color-scheme` so scrollbars and form
  controls match.
- The plot's background, the neutral point greys (Other, N/A), the selection ring and the contour
  lines come from tokens; the renderer reads them when it draws and re-renders on a theme change.
  Category palettes do not change; the default palettes get a contrast check against the dark
  background.
- The Mol\* viewer's background follows the theme.
- Exports always use the light values (white background, light greys), whatever the theme, and the
  figure editor previews them that way.
- The landing page, privacy page and docs keep their current look.

Mockup: [`mockups/workbench-dark.png`](mockups/workbench-dark.png).

### 17. Phones and tablets

The breakpoints of the mobile branch are kept (mockups: [`mockups/phone.png`](mockups/phone.png),
[`mockups/phone-landscape-and-tablet.png`](mockups/phone-landscape-and-tablet.png)):

- **951 px and wider**: the desktop workbench.
- **641–950 px**: plot on top with about 3/5 of the height; the sidebar moves below it, with the
  legend and the structure side by side.
- **640 px and narrower**: a fixed full-height screen that does not scroll, because the plot takes
  touch for pan and zoom. The app bar shrinks to the wordmark, the dataset name and a search button.
  The view bar keeps Projection and Color by and a "More" button; everything else (Contours, Filter,
  Import, Export, Theme, Help, Feedback) is in a "More" bottom sheet, with a dot on More when
  something inside is active. The sidebar becomes a panel under the plot that folds to its header,
  with Legend and Filter tabs. The structure opens as a bottom sheet folded to its header, so the
  plot and the tooltip stay visible; while it is expanded, a tap closes the tooltip.
- **Phone on its side** (landscape, 500 px tall or less): the page scrolls once past the bars to a
  plot-and-legend view exactly one screen tall; the structure opens on the right half.
- Touch affordances key on the pointer type (`pointer: coarse`), not the width: targets of at least
  40 px, legend row actions always visible, tap and double-tap on legend rows.

The mobile branch's 38 phone tests (Playwright project `mobile`, Pixel 7) are ported to the new
layout first and used as acceptance tests. The branch is then retired, not merged. Its spec's
requirement that the desktop layout stays unchanged is superseded.

### 18. Code structure targets

- No element file over about 800 lines; `legend.ts`, `control-bar.ts` and `publish-modal.ts` are
  split as described above.
- Deleted: the copied style mixins replaced by the kit, the 27 component custom properties nothing
  consumes, dead shell CSS (`Explore.css`), the site header on the explore page, the emoji and glyph
  icons, each dialog's own focus trap and fixed positioning, the inline-styled loading overlay.
- One way to do each recurring job: one popover and dialog system, one notifications module, one
  layer stack, one layout store, one icon set, one token file.

### 19. Docs media pipeline

`pnpm docs:images` (Playwright captures in `scripts/docs-screenshots/`, about 3,600 lines, plus
`convert-to-gif.ts`) is rewritten for the new layout:

- One set of page helpers ("open the filter panel", "select these proteins") shared by the e2e tests
  (`apps/web/tests/helpers/`) and the captures, so a layout change is fixed in one place.
- Controls are found by accessible role and name, which pierce shadow roots, instead of the about
  140 hand-written `shadowRoot` and `evaluate` lookups.
- Captures wait for signals (the plot has drawn, the dialog is open, the animation has ended)
  instead of the about 100 fixed `waitForTimeout` pauses.
- Each image is one entry (name, viewport, theme, steps, PNG or GIF); one runner handles file names,
  light and dark variants and the GIF conversion, with a size budget per GIF.
- All 17 screenshots, 9 GIFs and the 5 example thumbnails are regenerated. The thumbnails move here
  from the `examples-live` e2e suite, so every docs image comes from one pipeline. New captures cover the
  sidebar fold and resize, the floating structure, the selection bar, the filter panel, search
  messages, the theme switch and the phone layout. Images named after the old layout
  (`control-bar-*.png`) are replaced and deleted. The main screenshots get dark variants, shown when
  the docs are in dark mode.

### 20. Testing

- **Kit**: unit tests for keyboard use, focus return, ARIA roles and names. They run in a real
  browser (Vitest browser mode with Playwright), because jsdom has no `popover` support.
- **Feature elements**: the existing unit tests are kept and updated; new tests cover the layout
  store, the layer stack, the undo history, the scale function and search reporting.
- **E2E**: specs that pin the old layout are updated (`eat-visualization`, `numeric-binning`,
  `product-tour`, `legend-double-click`, `examples-live`, the perf scenarios, the shared locators in
  `helpers/explore.ts`). New specs cover the sidebar (fold, resize, persistence), docked and floating
  structure, the theme switch and first paint, the selection bar, the filter panel, search messages,
  Escape layering and undo.
- **Phones**: the ported mobile suite.
- **Accessibility**: `@axe-core/playwright` on the main states in both themes, plus a contrast check
  of the role tokens.
- **Performance**: `pnpm perf` at 573K must stay within the budgets recorded for PR #526, plus the
  new panel-toggle scenario.
- **Visual review**: the regenerated docs images serve as the before/after review set. The
  "pixel-identical to main" check of the perf PR does not apply, because the look changes on purpose.

## Risks / Trade-offs

- **[Large PR]** → Phases with green checkpoints, small commits, and this design as the review map.
- **[PR #526 changes before merging]** → This branch touches the renderer only in the scale function
  and the resize path; rebase as #526 moves.
- **[Performance regressions from the shell]** → The plot never animates; one resize per panel change;
  `pnpm perf` runs at the end of each phase that touches the plot or the legend.
- **[Keep-proportions surprises users with existing figures]** → Release note in the PR and the
  docs; the figure editor previews the new shape before export.
- **[Inter swaps in after first paint]** → `font-display: swap` with a metric-matched fallback
  (`size-adjust`) to limit layout shift; the font ships from the same origin.
- **[Popover, dialog or focus behaviour differs across browsers]** → Kit tests run in a real browser;
  e2e runs in Chromium; a manual pass in Safari and Firefox before merge.
- **[Emulation is not a phone]** (from the mobile branch) → A real-device pass on iOS Safari and
  Android Chrome before merge.
- **[Headless WebGL and Mol*]** → Tests assert placement and state, not the 3D render, as the
  mobile branch did.
- **[The mobile branch's work is lost]** → Its tests are ported first and pass on the new layout
  before the branch is retired.
- **[Embedders of `protspace-control-bar` break]** → `@protspace/core` is unpublished; the
  developer docs show the replacement elements.

## Migration Plan

- No data migration. URL parameters (`dataset`, `annotation`, `projection`, `tooltip`, `density`)
  are unchanged.
- localStorage: new keys `protspace:layout:v1` and `protspace:theme`. Per-dataset legend settings
  keep their key and format. The figure editor's saved state keeps its key.
- The tour gets a new storage key. New visitors get the full tour; returning visitors (the old key is
  present) get a short "What's new" tour once, covering the new layout, the sidebar and the theme
  switch.
- Rollback is reverting the merge; no stored data depends on the new UI.
